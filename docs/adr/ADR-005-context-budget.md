# ADR-005 · 上下文用「预算表 + 双条件外卸」，不靠「模型自己注意」

- 状态：已接受
- 日期：2026-11-09
- 相关：FR-401—405、§11

## 背景

S0.5 只有一条外卸规则：分箱表超 8 行就落盘。接 LLM 后会出现三类新问题：
① 16 行 × 6 字段的 Q1 原始 JSON 轻松 3k token；② 历史对话越滚越长；③ 累计工具结果把窗口挤爆。
不做预算的后果不是「答错」，而是**答到一半被截断**——比答错更难排查。

## 决策

**写死一张预算表**（`llm/budget.py`），超限按规则裁剪：

| 区块 | 预算(token) | 超限动作 |
|---|---|---|
| 系统指令 | 1200 | **不裁**（裁了丢「不许编数字」这类硬约束） |
| 工具 schema | 1500 | 只注册当前分支可用工具（从源头减） |
| 记忆 | 300 | 只取 top-3，按 confidence 排序 |
| 历史 | 1500 | 最近 3 轮全文 + 更早三元组（规则摘要，不用 LLM） |
| 单次工具结果 | 800 | 外卸为 artifact，只留 `ref_id + 摘要 + 统计量` |
| 累计工具结果 | 4000 | 早于 3 步的只留「工具名 + 关键统计量」 |
| 叙述上下文 | 1500 | 只给槽位 + ref_id，绝不给原始表 |
| 单轮总计 | 8000 | 提前收尾，声明「未穷尽」 |

**外卸用双条件**：`行数 > 8` **或** `估算 token > 800`，任一命中即落盘。
（S0.5 只有行数条件，会漏掉「3 行 × 20 列」这种宽表。）

**token 估算不引入 tokenizer**：中英混排按 `len(text)/2.2` 估，误差 ±15%，宁可早外卸。
理由：多一个 tokenizer 依赖，就多一个版本漂移源；预算的目的是「不爆」，不是「算准」。

## 后果

- 正面：不会截断；外卸后可回查（`summarize_ref`）；成本可预测。
- 负面：估算偏保守会让一些本可内联的结果被外卸，多一次工具往返。
- 纪律：**新增任何进上下文的区块，必须先在预算表里占一行**，否则视为无界增长。
