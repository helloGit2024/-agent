# 硬约束清单

> 「硬约束」= 违反就不用讨论了，必须改回来。每条都写明**违反的后果**与**谁来拦**。
> 与 `AGENTS.md` 的 `P-xx` 不重复：这里是**外部世界的约束**（合规/数据/依赖/环境），那里是**代码纪律**。

## 1. 合规与数据边界

| # | 约束 | 违反后果 | 谁拦 |
|---|---|---|---|
| C-01 | **明细不出域**：任何客户级行（apply_id、手机号、身份证、单笔借据）不得出现在回答、日志、MCP 响应、LLM prompt | 合规事故，产品直接下线 | `ev16` + `scan_outbound()` 静态扫描 + 代码评审 |
| C-02 | **模型内部信息不出域**：`score_col` 原始值、`base_dist`（训练期分布）、模型分箱切点细节只允许在本地进程内使用 | 模型被逆向，风控失效 | `get_model_health` 走本地（§8.6）；MCP 白名单不含分数列 |
| C-03 | **数据不落第三方**：LLM 只接收聚合后的数字与枚举（指标名、产品名、窗口），**不接收任何行级数据** | 数据出境/出域 | prompt 组装函数统一在 `llm/context.py`，禁传 rows（P-08） |
| C-04 | **审计不可关**：模型分、口径、权限判定、LLM 调用、工具调用、记忆写入六类事件必须留痕；写审计失败 = 业务失败 | 事后无法回答「当时为什么这么判」 | `AuditChain` + `ev18` + FR-506 |
| C-05 | **删除留痕**：任何删除（记忆/物化/会话）先软删，物理删除按 `retention_days` 延后并记审计 | 合规审查不过 | FR-303 |

## 2. 技术约束（不可协商）

| # | 约束 | 原因 |
|---|---|---|
| T-01 | **两个唯一计算入口**：`compute_model_metric()` 与 `catalog.compute`；不许第三条路径 | 口径漂移的唯一根源在原语外那 20 行（§8.3） |
| T-02 | **统计原语只许 `model_metrics` 调用**：`core/stats.py` 的 import 白名单只有 1 个文件 | 同上；CI 门禁 1 强制 |
| T-03 | **参数只收枚举**：不接受自由文本、SQL、表达式、切点、列名 | schema 一旦开放自由文本 = 把库交给 LLM（§9.3） |
| T-04 | **确定性优先**：CI、bootstrap、分箱切点、夹具生成、历史摘要全部固定 seed / 纯规则；LLM 只允许出现在「规划」与「叙述」两处 | 可复现性优先于灵活性（§16.2） |
| T-05 | **LLM 单出口**：业务代码禁止直连 provider | 没有统一出口就无法保证「被记录、被限流、能降级」（§12.2） |
| T-06 | **权限 fail-closed**：未知角色、未知指标、未知维度一律拒绝，不许「先放行再补」 | 越权一次就是事故 |
| T-07 | **零新依赖优先**：S1—S5 允许新增的第三方包仅 `mcp`、`psycopg`、`langmem`（可选）、provider SDK（可选）；新增其它包必须写 ADR | 保持「一条命令跑全仓」的能力 |
| T-08 | **解释器固定**：`/Users/tj/.workbuddy/binaries/python/envs/default/bin/python`（含 langgraph）；不得用系统 python | 系统 python 无 langgraph，跑不起来 |
| T-09 | **不打补丁式特判**：禁止在渲染层写 `if product == "P_CASH_001"` 这类业务特判 | 特判会绕过册子，等价于第二套口径 |
| T-10 | **FPD/MOB 前移不可绕过**：`check_maturity` 必须在取数之前 | 3 天窗口算 FPD7 是必错题 |

## 3. 环境与运行

| # | 约束 |
|---|---|
| E-01 | 开发机 macOS，无 Docker；MCP server 用 stdio，不依赖端口 |
| E-02 | 夹具库 `artifacts/v2_dialogue.db` 可随时重建（`make init`）；**不得手工改库**让测试变绿 |
| E-03 | 所有命令必须能在仓库根目录直接跑（Makefile 为准），不依赖外部脚本 |
| E-04 | 网络：允许访问 LLM API 与包索引；**禁止**把生产数据传到任何外部端点 |

## 4. 明确不做（范围边界，握手探针）

- 不做前端界面、不做多租户、不做移动端；
- 不做模型训练/调参、不做策略自动上线、不做审批流；
- 不替代报表平台；只保证「同参同数」；
- 不做自由探索式 SQL（探索沙箱是 S5 之后的独立议题）；
- 不接入实时流式数据（当前是 T+0 快照 + 日级物化）。

## 5. 违反时的处理

1. 门禁能拦的（T-01/T-02/T-03/T-05）→ 直接 CI 失败，改代码，不许改门禁。
2. 门禁拦不了的（C-01/C-02/C-03）→ 停下当前任务，先出 `docs/risk-register.md` 条目，再决定是否回滚。
3. 约束本身要改 → 先改本文件 + 补 ADR，再改代码。**顺序不能反。**
