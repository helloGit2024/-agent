# 风险登记簿

> 严重度：HIGH = 会导致错误结论/合规事故/架构返工；MED = 会拖慢或局部返工；LOW = 体验/维护性。
> **HIGH 必须有「闭合条件」，且闭合前不许进下一阶段。**

## 1. 对抗评审四视角（生成后必跑，L3 要求全跑）

| 视角 | 问法 | 本次发现 |
|---|---|---|
| ① 用户视角 | 没参与过访谈的人，只读文档能不能开工？ | 能——但有 2 处必须同时看代码才懂（见 R-07） |
| ② 攻击者视角 | 从哪下手能搞坏它？ | 3 条（R-03/R-04/R-05） |
| ③ 运维视角 | 上线第一个半夜谁被叫醒？ | 1 条（R-06） |
| ④ 会计视角 | 这些代价用户知道吗？ | 1 条（R-08） |

> 零发现 = 重跑，不是通过。

## 4. 每次阶段出口要回填的三件事

1. 本阶段新增风险 → 加行，写严重度与闭合条件。
2. 已闭合风险 → 状态改「已闭合」，附验证命令。
3. 阻塞项数量 → 必须 ≤3；超过就说明需求没谈清，回 `OPEN-QUESTIONS`。
